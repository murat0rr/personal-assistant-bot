# Roadmap и спецификация

## Архитектура (кратко)

Три канала входа — Telegram-бот (голос+текст), Tasker→Google Assistant relay,
Telegram Mini App — сходятся в единый backend-оркестратор. Там Groq
транскрибирует голос, Claude Haiku решает, какой сценарий это, и либо
обрабатывает сам, либо эскалирует на Sonnet для сложных задач. Дальше —
хендлер конкретного сценария, который читает/пишет в Notion и в
Postgres/Redis.

**UI: 4 кнопки-режима** (Задача / Заметка / Вопрос / Напоминалка) —
постоянная reply-клавиатура в Telegram. Тап → бот спрашивает содержимое →
следующее сообщение идёт напрямую в нужный хендлер без обращения к
classify_intent (экономия). Без кнопки — свободный ввод по-прежнему
классифицируется автоматически тем же Haiku, на тот же набор из 4 intent'ов.

## Notion: базы данных

**Tasks** — Name (title), Due date/Date (date — название варьируется от
базы к базе, код проверяет оба), Priority (select), Status (select или
нативный Notion status — код определяет тип сам), Source

**Notes** — Name (title), Content (text)

**Diary** — Name, Date, Physical/Social/Productivity/Happiness (number,
1-3), Highlight, Reflection, Summary (авто от Claude, только если
пользователь реально что-то написал в Highlight/Reflection)

**Habits** — Name, Streak (number), Last checked (date), Target frequency

Важно: используем свойства базы данных (не текстовые чек-листы внутри
страницы) — так остаётся возможность добавить автоматизации позже.

## Напоминалки (не в Notion — в Postgres)

Заменяют изначальный план с Notion-базой Subscriptions. Пользователь
описывает расписание человеческим языком ("в последний день месяца
напомни выбрать кэшбэк", "каждую среду", "раз в 5 дней", "5 сентября") —
Claude (Haiku) разбирает в структуру (`schedule_kind`: once/monthly_day/
weekly_day/interval_days), хранится в таблице `reminders`. Проверка раз в
день в то же время, что рассылка задач (8:00). `/reminders` в слэш-меню —
список с кнопками удаления.

| # | Фича | Триггер |

| F2+F3 | "Вопрос" — рецепты/учёба/выбор/подбор по бюджету, объединены в один хендлер (веб-поиска нет — прокси не поддерживает нативный тул, отвечает по знаниям модели с оговоркой) | кнопка "Вопрос" / автоклассификация |
| F4 | Вечерний дневник — проактивные вопросы, сборка записи | по расписанию |
| F5 | Утренняя сводка задач | по расписанию |
| F6 | Разбор домашнего задания по фото → план подготовки со ссылками | фото |
| F7 | ~~Трекер подписок~~ → заменено общей системой напоминалок (см. выше) | кнопка "Напоминалка" / автоклассификация + по расписанию |
| F8 | Трекер привычек со streak, напоминание при пропуске | по расписанию |
| F9 | Финансовый дайджест раз в месяц — пользователь присылает CSV-выписку из Т-Банка документом, Sonnet считает категории | документ (CSV) + напоминание-гайд по расписанию |
| F10 | Экранное время — Tasker раз в день шлёт дневной итог на webhook, наутро бот присылает сводку | webhook + расписание |

мобильного приложения кроме Mini App.

## Фазы разработки

### Phase 0 — Skeleton
Repo structure, pyproject (uv), .env.example, Docker Compose (bot, api,
postgres, redis, caddy-stub). aiogram-бот отвечает на /start только для
TELEGRAM_USER_ID.
**Готово когда:** `docker compose up` поднимает всё, /start отвечает.

### Phase 1 — F1 + интеграция с Notion
`notion.py` — обёртка над API (create/update page). STT (Groq) за
интерфейсом. Haiku извлекает title/due date/priority из сообщения.
**Готово когда:** голосовое "задача купить хлеб завтра важно" создаёт запись
в Notion Tasks с нужными полями.

### Phase 2 — LLM-роутинг + F2
Оркестратор: Haiku классифицирует intent → роутинг к хендлеру; Sonnet — для
сложных сценариев. Web search интеграция (нативный tool у Claude API).
**Готово когда:** "подбери аэрогриль до 5000" отдаёт 3-5 вариантов со
ссылками и ценами.

### Phase 3 — pull-синк Notion + Mini App
Входящие Notion webhooks оказались источником постоянных проблем именно в
этой среде разработки (сеть режет туннели, антивирус блокирует ngrok) —
решили не зависеть от публичного URL для синка статусов. Вместо
`/webhooks/notion`: `core/notion_sync.py` тянет все задачи из Notion и
апсертит в Postgres — по расписанию (APScheduler, раз в день) и по
требованию (при открытии Mini App). Уведомление в Telegram шлётся, когда
плановый синк обнаруживает реальное изменение статуса. Mini App: список
задач + кнопка "выполнено" → обновляет Postgres и Notion (без изменений,
эта часть не зависела от вебхуков).
**Готово когда:** статус, изменённый в Notion, попадает в Telegram при
следующем плановом синке или при открытии Mini App; кнопка "выполнено" в
Mini App синхронна с Notion сразу.

### Phase 4 — Scheduler + F4, F5
APScheduler джобы. aiogram-dialog для многошагового вечернего опроса. Redis
хранит состояние "жду ответ N из M".
**Готово когда:** бот сам присылает утреннюю сводку и вечером задаёт вопросы
дневника.

### Phase 5 — F3, F8 + пересмотр UI (кнопки-режимы, общие напоминалки)
Изначально планировали F7 через Notion-базу Subscriptions — по ходу решили
сделать общую систему напоминалок в Postgres (см. раздел выше) вместо
привязки к подпискам конкретно, и заодно ввели 4 кнопки-режима
(Задача/Заметка/Вопрос/Напоминалка), объединив F2+F3 в один хендлер.
Habits (F8) — через Notion+Mini App, без изменений.
**Готово когда:** рецепт/вопрос отвечает в чат; привычки отмечаются в Mini
App со streak; напоминалка, заданная человеческим языком, сохраняется и
срабатывает по расписанию; `/reminders` показывает и позволяет удалить.

### Phase 6 — F9, F10, F11
**F9**: 1-го числа месяца в 8:00 бот присылает напоминание с гайдом, как
выгрузить CSV-выписку из Т-Банка; пользователь в любой момент шлёт файл
документом (независимо от кнопок-режимов) — Sonnet сама определяет
колонки CSV и считает траты по категориям, топ-статьи, крупные операции.

**F10**: `POST /webhooks/tasker/screen-time` (секрет — заголовок
`X-Tasker-Secret`, сверяется с `TASKER_WEBHOOK_SECRET`) принимает дневной
итог экранного времени, апсертит в Postgres по дате. В 8:00 бот шлёт
сводку за вчера, если данные пришли (тихо пропускает, если Tasker не
сработал — без спама).

**F11**: по воскресеньям в 19:00 бот собирает саммари недели — выполненные
и просроченные задачи (Postgres-кэш), средние оценки и хайлайты дневника,
стрики привычек (оба — напрямую из Notion). Финансы и экранное время в
ревью не входят — у них свои сводки.

**Готово когда:** все три сводки приходят по расписанию корректно.

### Phase 7 — F6, F12
Vision (Claude) для фото домашки. Утренний брифинг объединяет F5 + погоду +
F8 + дедлайны целей.
**Готово когда:** фото задания даёт план подготовки; утренний брифинг — одно
сообщение со всем сразу.

### Phase 8 — Deployment & CI/CD
